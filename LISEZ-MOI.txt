MONGANGA — FRONTEND / MISES EN PAGE RESTAURÉES
Patient · Médecin · Administration

LANCER LE PROJET
Décompressez l'archive, ouvrez un terminal dans app-main, puis :

    npm start

Ouvrez http://localhost:8080
Node.js suffit pour ce serveur local. Les polices, icônes et images sont
incluses ; le mode démo ne dépend d'aucun CDN. Aucun build n'est nécessaire.
N'ouvrez pas les pages par un double-clic : utilisez HTTP/HTTPS.

TESTER LES TROIS ESPACES
Sur la page Connexion, cliquez sur Patient, Médecin ou Admin, puis sur
Se connecter. Ces boutons remplissent des identifiants de démonstration :
- Aline Kabila : patient principal.
- Second patient : saisir patient2@monganga.cd et Demo1234 pour vérifier
  la séparation des données.
- Médecin : Dr Ilunga. Les autres comptes de test utilisent
  dr.<identifiant>@monganga.cd et Demo1234 (identifiants du catalogue).
- Administration : utilisateurs, candidatures et transactions.

Aucun mot de passe réel n'est nécessaire en mode démo. Le bouton « Changer
de compte » permet de suivre le même rendez-vous depuis plusieurs rôles.
Conservez le même onglet pour partager ces données de démonstration.
Les modifications survivent au rechargement dans cet onglet. La fermeture
ou la réinitialisation de la démo peut les supprimer.
Utilisez uniquement des noms, informations médicales et documents fictifs.

PARCOURS CONSEILLÉ
1. Patient : rechercher Dr Ilunga, choisir un créneau et tester un paiement.
2. Simuler un échec, réessayer puis simuler la réussite.
3. Ouvrir Mes RDV : déplacer ou annuler un rendez-vous.
4. Changer pour Dr Ilunga : consulter l'agenda, ouvrir la consultation,
   envoyer un message et terminer la consultation.
5. Émettre une ordonnance, puis revenir au compte patient pour la consulter.
6. Administration : examiner les candidatures, modifier les statuts et
   traiter un remboursement de démonstration.

L'inscription patient possède une vérification OTP simulée : code 123456.
La candidature médecin conserve les noms des fichiers dans la démo, mais
n'envoie aucun fichier. Le test caméra/micro utilise le navigateur local.
La démo ne contacte aucun médecin distant et ne débite aucun paiement.

CONNECTER LE BACKEND
Lire BACKEND_INTEGRATION.md, puis docs/openapi.json.
Configurer assets/js/config.js avec mode: 'api' et l'URL du backend.
Toutes les actions passent par le service partagé assets/js/data.js.
Sans serveur réel, le mode API affiche des erreurs et ne revient pas à la démo.
MaishaPay, OTP/SMS/email, vidéo, stockage privé et PDF/QR signés restent à
implémenter par le développeur backend avec les raccords fournis.

TESTS REPRODUCTIBLES
Utiliser une version de Node compatible avec package.json. Les essais de
cette livraison ont été exécutés avec Node 24.19 et Chromium 153.

    npm ci
    npm test

43 tests métier, session, API, DOM, fichiers liés et styles.

    npx playwright install chromium
    npm run test:browser
    npm run test:api

Le premier test navigateur couvre les parcours, les menus et les pages à
360, 768, 1024 et 1440 pixels. Le second vérifie le mode API avec des réponses
HTTP contrôlées, sans backend réel. Lancer les suites l'une après l'autre ;
chacune démarre puis arrête son propre serveur local sur le port 8080.
Arrêtez d'abord un éventuel « npm start » ou choisissez un autre PORT.

DOCUMENTATION

Le serveur npm start est réservé au développement. Pour une mise en ligne,
servir seulement les HTML et assets nécessaires, en HTTPS, et finaliser les
services réels ainsi que les textes publics avec les responsables du projet.
